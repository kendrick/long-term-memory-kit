# A Hosted ltm Takes Its Consumer Repo From the Environment

`ltm mcp --http` runs in a container whose working directory has no git origin, so every `query` without `facets` returned only Org-wide Records, and agents answered from that subset as if it were everything. A hosted server takes its Consumer repo from `LTM_CONSUMER_REPO=<org>/<repo>` and looks it up in the Bank's `consumers` map, the same lookup `ltm query` makes with a checkout's origin. The variable wins over the working directory, and explicit `facets` win over the variable. The guide's advice to pass `facets` stays as the fallback, but on its own it works only when every agent author reads that paragraph and every model obeys it. A `repo` input on `query` would let one server serve every Consumer repo, but it grows the tool's schema and still needs the agent to know which repo it answers for, the same knowledge `facets` asks of it. Returning every Record when no origin maps would change what an unmapped query means everywhere and flood callers with other teams' Records. One server serves one Consumer repo, so a team with several runs a server per repo or has its callers pass `facets`.
