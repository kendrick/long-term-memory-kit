# The Four Memory Types Stay Closed

A Bank can't declare its own memory types. A Record that isn't a Decision, PolicyRule, or Exception is a Context, and a Bank that needs to tell kinds of Context apart gives them a `kind` key. The Bank declares that key under `custom_keys` with an `enum` and `memory_types: [Context]`, so `ltm validate` rejects a misspelled kind. A Bank that wants each kind in its own folder nests it under the Context folder. Every Record found below that folder is a Context, so `_memory/context/inventory/` works without config.

Each of the four types carries behavior beyond its name. `ltm validate` requires a Decision's body sections and an Exception's link to a PolicyRule. `ltm digest` groups each PolicyRule with its Exceptions and drops an Exception past its end date, and `ltm propose` writes a different template for each type. A Bank-declared type would get none of that, so it would be a Context with a different label. Opening the set would still mean changing `MEMORY_TYPES`, the `memory_type` enum in the Record schema, `folders` and `recall.collections` in the Bank config schema, `TEMPLATES`, the digest's sections, and every CLI check that names the four. Lean Over Comprehensive in `docs/design-forces.md` says a field earns its place by observed need. A new type would need new behavior to earn its place, and no Bank has asked for any.
